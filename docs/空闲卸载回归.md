# 0.2.3-p1 OCR 推理子进程与闲置卸载回归

0.2.3 及之前版本在桌面工作线程（`src/jobs.rs`）和 HTTP 服务（`src/server.rs`、`src/server_document.rs`）中进程内常驻 ONNX Runtime 与 OCR 模型会话；完成一次识别后，模型权重、`onnxruntime.dll` 与内存池长期占用进程内存，不会随闲置释放。

## 实现方式

参考 `YuYbUuRu` 的子进程推理与闲置退场模式，0.2.3-p1 新增 `src/ocr_worker.rs`：

- 通过 `--ocr-worker --models <DIR>` 启动无窗口（`CREATE_NO_WINDOW`）推理子进程，主进程与子进程经标准输入/输出二进制帧协议传输原始 RGB 像素与结构化识别结果，主进程本身不再加载 `onnxruntime.dll`。
- 推理子进程纳入 Windows Job Object（`JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`），主进程正常退出或异常终止时均自动清理子进程，不留孤儿进程。
- 连续识别任务复用同一推理子进程与模型会话；无 OCR 任务达到闲置阈值（默认 90 秒，支持在“全局设置 → 高级 → OCR 推理 → 闲置卸载时间（秒）”或 `--idle-seconds` 调整，设为 `0` 表示常驻）后，主进程发送 `Shutdown` 使推理子进程优雅退出，完整释放子进程独占内存与工作集，随后在主进程调用 `EmptyWorkingSet` 收缩主进程工作集。
- `jobs.rs` 与 `OcrService` 均采用按剩余时间单次 `recv_timeout` 等待（未启动子进程时阻塞 `recv`），闲置期零轮询、零额外 CPU 唤醒。
- HTTP 服务（`/api/ocr` 与 `/api/doc/*`）共享同一 `OcrService` 调度器与推理子进程，消除原有双份模型常驻。

## 实测对比

2026-11-24，Windows 11 x64，Rust 1.95。使用隔离配置与合成测试图 `verification/fixtures/compact.png`，在相同 3 秒闲置阈值下对比 `0.2.3` 基线与 `0.2.3-p1` 便携版候选产物（`WfZiUiBp.exe` SHA-256 `32150a3b2281d893993a75c0b36c3ee5d384b4219a2d375c85c50f24ef8af8e4`）：

| 场景与指标 | 0.2.3 基线 | 0.2.3-p1 候选 | 变化 |
| --- | --- | --- | --- |
| 托盘识别后闲置工作集（总 WS） | 62.68 MiB | 0.88 MiB | -98.6% |
| 托盘识别后闲置私有内存（总 PM） | 60.11 MiB | 3.31 MiB | -94.5% |
| 托盘卸载后 3 秒空闲 CPU | 15.625 ms | 0 ms | 零唤醒 |
| HTTP 识别后闲置工作集（总 WS） | 80.59 MiB | 0.12 MiB | -99.9% |
| HTTP 识别后闲置私有内存（总 PM） | 67.93 MiB | 2.83 MiB | -95.8% |
| 闲置后推理子进程数量 | 进程内常驻 | 0 | 完整退出 |
| 闲置后二次识别拉起与结果一致性 | — | 通过（1 子进程，文本一致） | 无缝恢复 |
| `--quit` 退出与主进程强杀清理 | — | 通过（0 孤儿进程） | Job Object 生效 |

注：上述小图样本已体现进程内常驻与子进程退出后的结构性差距；面对整页截图、多页文档或大分辨率图像时，推理子进程工作集常达 130–200 MiB 以上，闲置退出后同样完整归还给系统。

- 16 项 release 单元测试全部通过（含新增的帧协议往返、非法像素负载拒收、未启动闲置退场空操作、`EmptyWorkingSet` 调用安全测试）。
- 桌面图标校验通过，4 档尺寸（16/32/48/256 px）逐帧匹配原版 ICO。
- HTTP 接口全量回归通过，覆盖 `/api/ocr`、扩展二维码与 Code128、PDF 文档任务、多格式导出、清理后 404 以及密码保护 PDF 解锁。
- 命令行 `--path` 单次离线识别通过。
